01 Check a URL

Check on-chain runs a consensus round and writes the verdict (needs a wallet on Studionet; about a minute). Look up reads the stored verdict without a transaction and works without a wallet. A page that cannot be fetched ends unchecked — no verdict is written from partial data.

02 Recent entries

Newest first. Every entry links to its stored signals. Dispute or request a re-check from the entry itself; both are on-chain writes and need a wallet.

04 How a check works

  1. Submit. Any account can ask the contract to check a URL.
  2. Fetch. The leader fetches the page; every validator fetches it again and derives the same signals — scheme, host shape, brand impersonation, password field, off-host form, blocklist.
  3. Agree. The verdict is written only when validators agree exactly on all ten compared signals. A password field alone is not a warning; a blocklisted host is malicious by rule.

The verdict is a deterministic rule, not a model opinion. The same URL checked twice gives the same verdict, and any reviewer can re-derive it from the stored evidence. Source and tests: github.com/syariffadilla/SafeLink-On-GenLayer.
